# 개발지시서 4: QR 코드로 대상목록 등록 (메일 파일 방식과 함께 사용)

> Claude Code에게: `CLAUDE.md`와 `docs/`의 지시서 1~3을 먼저 읽어 줘. **지시서 3(기관 메일 배포 전환)까지 구현 완료**된 상태를 전제로 한다.
> 이 문서는 기존 「목록 파일(.sajin) → 기관 메일 → 휴대폰에서 불러오기」를 **그대로 두고**, 더 빠른 등록 수단으로 **QR 코드**를 추가하는 작업이다.
> 지시서 3의 암호화 모듈(`src/listcrypto.js`), 목록 형식, 병합 규칙, 팀 구분, 관리 화면(`admin.html`, `#admin`)을 재사용한다.
> 담당자는 비개발자다. 끝나면 한국어로 "무엇이 바뀌었는지 / 어떻게 쓰는지 / 휴대폰에서 어떻게 확인하는지"를 단계별로 알려줘.
> 이 파일은 `docs/대상목록_QR등록_개발지시서.md`에 두고 맨 아래 "작업 기록"에 진행 상황을 남겨 줘.

## 1. 목적
지금은 팀원이 **엑셀(또는 목록 파일)을 휴대폰에 받아 → 앱에서 파일을 골라** 불러온다.
이를 **PC 화면(또는 인쇄물)의 QR을 휴대폰 카메라로 찍으면 바로 등록**되도록 줄인다.

```
[내부망 PC · admin.html]                      [휴대폰]
엑셀 선택 → 미리보기 → 「QR 만들기」             카메라로 QR 찍기
   → 화면에 QR (또는 인쇄)  ── 화면/종이 ──▶      → 앱 열림 → (처음만) 팀 비밀번호
                                              → 우리 팀 목록 등록
```
- 목록은 **PC 화면 → 휴대폰 카메라**로만 이동한다. 메일·서버 어디에도 저장되지 않는다
- QR 안의 목록은 **팀 비밀번호로 암호화**되어 있다 (QR 사진이 유출돼도 비밀번호 없이는 못 읽음)
- 기존 메일 파일 방식은 그대로 둔다 (PC 앞에 없는 팀원용)

## 2. QR에 담는 내용 (형식)
QR은 앱 주소 링크다. **목록은 주소의 `#` 뒤에만** 넣는다 (`#` 뒤는 서버로 전송되지 않음).
```
https://<아이디>.github.io/sajin/#q=1.2.K7F2.<데이터>
                                   │ │  │     └ 암호화된 목록 조각 (base64url)
                                   │ │  └ 목록 묶음 식별값 (listId 앞 4자 + listVersion 해시 일부)
                                   │ └ 전체 조각 수
                                   └ 이 조각 번호
```
- **크기 줄이기** (QR 장수를 줄이는 것이 핵심)
  1. 목록 JSON을 **짧은 키**로 변환 (예: `facility`→`f`, `location`→`l`). 변환표는 `src/qrcodec.js` 한 곳에서 관리하고 앱·관리 화면이 공유
  2. QR에 넣지 않는 항목: `purpose`(앱 기본값), `resultHeading`, `defaultLabel` 등 고정값, 빈 값
  3. 압축(deflate) → 암호화(AES-256-GCM, 지시서 3과 같은 키·솔트) → base64url
  4. QR용 데이터에는 `keyCheck`를 넣지 않는다. 복호화 실패(GCM 인증 실패)로 비밀번호 오류를 판별
  - 압축은 **fflate**(MIT, 버전 고정 `0.8.2`)를 파일 안에 내장해서 사용 (브라우저 내장 CompressionStream은 구형 아이폰에서 없을 수 있음)
- **조각 나누기**: 조각 하나의 주소 길이를 **1,100자 이하**로 한다 (화면·인쇄물에서 잘 찍히는 크기, 오류정정 M). 넘으면 자동으로 2장, 3장…으로 나눈다
  - 목표: 시설 10곳 이하(연락처 제외)는 **1장**. 실제 가짜 데이터로 측정해 결과를 작업 기록에 남길 것
  - 4장을 넘으면 관리 화면에서 "QR이 너무 많습니다. 연락처 빼기(체크) 또는 메일 파일 방식을 권합니다" 안내
- 암호화는 **조각으로 나누기 전 전체에 한 번** 하고, 휴대폰은 조각을 모두 모은 뒤 복호화한다

## 3. 관리 화면 변경 (`admin.html`, `#admin` 공통)
지시서 3의 「목록 파일 만들기」 옆에 **「QR 만들기」** 버튼 추가.
1. 비밀번호 → 팀 이름 → 엑셀 → 미리보기 (기존과 같음)
2. 「QR 만들기」 → 화면에 QR 표시
   - QR 위: **팀 이름, 회차 이름, 시설 수, 만든 시각**, 여러 장이면 "1 / 2"
   - QR 아래 안내: "휴대폰 기본 카메라로 찍으세요. 2장이면 순서 상관없이 모두 찍으세요"
   - QR은 화면 높이의 70% 정도로 크게, 흰 바탕·여백(quiet zone 4칸) 확보, 다크 모드에서도 흰 바탕 유지
   - 여러 장이면 「다음 QR ▶」 넘기기 + 「한 화면에 모두 보기」
3. 「인쇄용 보기」: A4 한 장에 QR(최대 4장)과 팀 이름·회차·만든 시각·사용 안내만 인쇄
   - **시설물명·주소 등 목록 내용은 인쇄 페이지에 글자로 넣지 않는다** (QR 안에만, 암호화 상태)
   - 출장계획(안) 출력물에 붙일 수 있도록 「QR만 작게(4cm) 인쇄」 옵션
4. 옵션: 「연락처·담당자 빼기」(QR 장수 줄이기용, 기본 해제), 「출장자 이름 빼기」(빼면 자동 팀 구분이 안 된다는 경고)
- QR 생성은 **qrcode-generator**(MIT, kazuhikoarase, 버전 고정 `1.4.4`)를 파일 안에 내장. `admin.html`은 지시서 3대로 **완전 오프라인**(외부 요청 0건) 유지
- 비밀번호·엑셀 내용·QR 이미지를 저장하지 않는다 (화면을 닫으면 사라짐)

## 4. 휴대폰 앱 변경

### 4-1. 카메라 앱으로 찍은 경우 (기본)
- 앱이 열릴 때 주소에 `#q=`가 있으면 **가장 먼저** 처리한다
  1. 조각을 IndexedDB의 「받는 중인 QR」에 저장 (같은 묶음 식별값끼리 모음)
  2. 즉시 `history.replaceState`로 주소에서 `#q=…`를 지운다 (방문 기록에 남지 않게)
  3. 모든 조각이 모이면 → 복호화 → 지시서 3의 불러오기 결과 처리(새 목록 등록 / 같은 listId 새 버전 병합 / 옛 버전 무시)
  4. 덜 모였으면 화면 위에 진행 표시: "3팀 목록 QR **1 / 2** 받음 — 나머지 QR을 찍어 주세요" (+ 받은 조각 번호 표시)
- 키가 없으면 지시서 3의 팀 비밀번호 카드 → 내 이름 입력 흐름. 비밀번호를 넣으면 이어서 등록 완료
- 복호화 실패: "팀 비밀번호가 맞지 않거나 QR이 손상되었습니다. 비밀번호를 다시 입력하거나 QR을 다시 찍어 주세요"
- 받다 만 조각은 **24시간 후 자동 삭제**

### 4-2. 앱 안에서 QR 찍기 (권장)
카메라 앱은 휴대폰 기종에 따라 **다른 브라우저**(예: 삼성 인터넷)로 링크를 열 수 있다. 그러면 평소 쓰던 브라우저와 저장 공간이 달라 목록이 안 보인다. 이를 막기 위해 앱 안에도 QR 찍기 기능을 둔다.
- 목록 화면에 **「QR 찍기」** 버튼 (「목록 파일 불러오기」와 나란히)
- `getUserMedia`로 후면 카메라 → **jsQR**(Apache-2.0, 버전 고정 `1.4.0`, 파일 안에 내장)로 판독. `BarcodeDetector`가 있으면 우선 사용
- 여러 장이면 카메라를 끄지 않고 계속 찍으며 "1 / 2 받음" 표시, 다 모이면 자동 종료 후 등록
- 카메라 권한 거부 시: "설정에서 카메라 권한을 허용하거나, 기본 카메라 앱으로 QR을 찍어 주세요"
- 판독한 주소가 이 앱 주소(`#q=` 형식)가 아니면 무시 ("이 앱용 QR이 아닙니다")

### 4-3. 다른 브라우저로 열렸을 때 안내
- `#q=`로 열렸는데 이 브라우저에 **기존 시설물·키가 하나도 없고**, 사용자 에이전트가 삼성 인터넷 등 평소와 다른 브라우저로 보이면 안내:
  "평소 쓰는 브라우저가 아니면 목록이 따로 저장됩니다. 평소 쓰는 브라우저에서 앱을 열고 「QR 찍기」로 찍어 주세요" + 「여기에 그냥 등록」 버튼

## 5. 보안 · 개인정보
- QR 데이터는 반드시 암호화 상태. **평문 목록을 QR·주소·인쇄물·로그에 넣지 않는다**
- 목록은 주소의 `#` 뒤에만. `?` 쿼리 사용 금지
- 처리 직후 주소에서 `#q=` 제거 (`history.replaceState`)
- 앱은 QR 처리 중에도 **외부 요청을 하지 않는다** (네트워크 기록으로 테스트)
- 내장 라이브러리 3종(fflate, qrcode-generator, jsQR)은 **버전 고정 + 라이선스 주석 유지**, `CLAUDE.md`의 "허용 외부 코드" 목록에 추가. CDN에서 불러오지 않는다
- 테스트·문서에 실제 시설 정보·비밀번호 사용 금지 (`test-only-passphrase-0000`, 가짜 엑셀만)

  7. 전 과정에서 앱의 외부 요청 0건
  8. 화면 캡처: 관리 화면 QR(1장·2장), 인쇄용 보기, 휴대폰 진행 표시, 등록 완료 → `tests/out/`

## 8. 운영방법 문서에 추가할 내용 (쉬운 말)
**팀장 (출장 전)**
1. 내부망 PC에서 `admin.html` → 비밀번호 → 팀 이름 → 엑셀 → 「QR 만들기」
2. 팀원이 모여 있으면 화면의 QR을 각자 찍게 하기 / 출장계획(안)에 붙이려면 「인쇄용 보기」로 인쇄
3. PC 앞에 없는 팀원에게는 지금처럼 「목록 파일 만들기」 → 기관 메일

**팀원 (휴대폰)**
1. 앱을 열고 「QR 찍기」 → 화면이나 종이의 QR 비추기 (기본 카메라 앱으로 찍어도 됨)
2. QR이 2장 이상이면 모두 찍기 ("1 / 2 받음" 확인)
3. 처음이면 팀 비밀번호·내 이름 입력 → 우리 팀 목록 확인

**주의**
- 기본 카메라로 찍었는데 목록이 안 보이면, 평소 쓰는 브라우저에서 앱을 열고 「QR 찍기」로 다시 찍기
- QR 인쇄물은 암호화되어 있지만, 출장이 끝나면 일반 문서처럼 파기

## 9. 담당자에게 남길 확인 질문
1. QR을 주로 **PC 화면**에서 찍게 할까요, **인쇄물**(출장계획 등)에 붙일까요? (인쇄 크기 기본값 결정)
2. 팀원 휴대폰은 아이폰·갤럭시가 섞여 있나요? (갤럭시 기본 카메라가 삼성 인터넷으로 여는지 실제 확인 필요)
3. QR에 연락처를 넣을까요? (넣으면 QR이 커지거나 장수가 늘어남)
