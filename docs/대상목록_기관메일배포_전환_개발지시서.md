# 개발지시서 3: 대상목록 배포 방식을 「기관 메일 전달」로 전환

> Claude Code에게: `CLAUDE.md`, `docs/엑셀_대상목록_연동_개발지시서.md`(지시서 1), `docs/대상목록_사전등록_개발지시서.md`(지시서 2)를 먼저 읽어 줘.
> **지시서 2는 구현 완료된 상태**다. 이 문서는 지시서 2의 "GitHub에 암호화 목록을 올리고 휴대폰이 자동으로 받는 방식"을 걷어내고,
> **"암호화 목록 파일을 기관 메일로 보내고 휴대폰에서 불러오는 방식"**으로 바꾸는 작업이다.
> 지시서 2에서 만든 암호화 모듈, 팀 구분, 병합 규칙, 관리 화면은 **최대한 재사용**한다.
> 담당자는 비개발자다. 끝나면 한국어로 "무엇이 바뀌었는지 / 어떻게 쓰는지 / 휴대폰에서 어떻게 확인하는지"를 단계별로 알려줘.
> 이 파일은 `docs/대상목록_기관메일배포_전환_개발지시서.md`에 두고 맨 아래 "작업 기록"에 진행 상황을 남겨 줘.

## 1. 바꾸는 이유
- 기관이 보수적이라 **외부 서버(GitHub·클라우드)에 기관 정보를 보관하는 것**은 암호화를 해도 설득이 어렵다
- 특히 GitHub는 공개 저장소라 암호화 파일을 누구나 내려받을 수 있고, **지워도 이력에 영구히 남는다**
- 실원들은 **휴대폰에서 기관 메일을 받을 수 있다** → 대상목록은 기관 메일로만 오가게 한다

## 2. 바뀐 뒤의 원칙
| 구분 | 위치 | 비고 |
|---|---|---|
| 앱 프로그램(빈 앱) | GitHub Pages | 지금 그대로. **기관 정보 없음** |
| 대상목록 | **기관 메일 첨부파일**로만 전달 | 팀 비밀번호로 암호화된 파일 |
| 사진·작성 내용 | 각자 휴대폰 | 지금 그대로 |
| 보고서 전송 | 휴대폰의 **기관 메일 앱**으로 첨부 | 앱 안내 문구를 기관 메일 기준으로 변경 |

- 외부 서버에 **대상목록을 저장하는 기능은 모두 제거**한다 (자동 받아오기, `data/lists/`)
- 기관 메일이 내부 경로라도 **목록 파일 암호화는 유지**한다 (메일 오발송·전달, 휴대폰 분실 대비)

```
[담당자/팀장 PC]                               [실원 휴대폰]
엑셀 → 관리 화면에서 암호화 파일 만들기                기관 메일 앱에서 첨부파일 받기
      (대상목록_3팀_26-4차.sajin)                  → 「파일에 저장」
   → 기관 메일에 첨부해 팀원에게 발송  ───기관 메일───▶ → 앱 「목록 파일 불러오기」
                                                → 최초 1회 팀 비밀번호 → 우리 팀 목록
```

## 3. 작업 A — GitHub에서 목록 흔적 제거 (가장 먼저)
1. `git log --all --oneline -- data/lists` 로 **실제로 목록 파일이 올라간 적이 있는지** 확인하고 결과를 담당자에게 보고
2. 올라간 적이 없으면: `data/lists/` 폴더와 관련 코드만 제거하고 4장으로
3. 올라간 적이 있으면:
   - 담당자에게 먼저 설명하고 **승인을 받은 뒤** 진행: "이전에 올린 암호화 목록이 저장소 이력에 남아 있습니다. 이력에서 완전히 지우려면 저장소 기록을 다시 쓰고 강제로 올려야 합니다"
   - `git filter-repo --path data/lists --invert-paths` (없으면 설치 방법 안내) → `git push --force`
   - 작업 전 저장소 전체를 `../sajin-backup-YYYYMMDD` 로 복사해 둘 것
   - **팀 비밀번호 교체를 권고**: 누군가 이미 파일을 내려받았을 수 있으므로 (교체 방법은 7장)
4. `scripts/check_safe_to_commit.mjs`에 `data/lists/`, `*.sajin` 커밋 차단 추가, `.gitignore`에 `*.sajin` 추가

## 4. 작업 B — 목록 파일 형식 (`.sajin`)
- 지시서 2의 팀 칸 파일(`team-NN.enc`) 내용 형식을 그대로 쓰되, 팀 칸 번호(`slot`) 대신 **팀 식별값**을 넣는다
```jsonc
// 대상목록_3팀_26-4차.sajin  (JSON 텍스트, 확장자만 .sajin)
{
  "type": "sajin-list", "v": 2,
  "alg": "AES-256-GCM",
  "kdf": { "name": "PBKDF2-SHA256", "iter": 600000, "saltId": "2026A" },   // 앱에 내장된 솔트의 이름
  "keyCheck": "…", "iv": "…", "ct": "…",
  "createdAt": "2026-10-28T09:00:00+09:00"
}
// 복호화된 내용
{
  "listId": "랜덤 UUID",                 // 같은 팀·같은 회차 목록을 다시 보내면 같은 listId 유지 (갱신 판별용)
  "listVersion": "20261028-0900",
  "team": { "name": "3팀 (부산권)", "members": ["홍길동", "김철수"] },
  "batch": { "id": "26-4", "name": "26년 4차 사실관계조사 시설물", "dates": [...] },
  "sites": [ ... 지시서 1 importer 결과 ... ]
}
```
- **솔트**: 서버에서 받지 않는다. `data/crypto.json`(솔트만, 비밀 아님)을 **빌드할 때 앱·관리 화면에 내장**한다. 그래야 휴대폰에 저장된 키로 새 파일도 비밀번호 없이 열린다
  - 비밀번호 교체 시 새 솔트(`saltId` 새 이름)를 추가하고 앱을 다시 배포. 이전 솔트는 목록에 남겨 이전 파일도 열 수 있게 하되, 휴대폰은 이전 키를 2주 후 자동 삭제
- 파일 이름 규칙: `대상목록_{팀이름}_{회차id}.sajin` (특수문자 제거)
- 기관 메일 첨부 제한에 걸리지 않도록 **텍스트 파일 크기 100KB 이하** 확인 (보통 수 KB). 기관 메일이 낯선 확장자를 막으면 `.txt`로 저장하는 옵션 제공 (`settings.listExt`)

## 5. 작업 C — 관리 화면 (목록 파일 만들기)

### C-1. 오프라인 관리 파일 `admin.html` (신규, 핵심)
엑셀은 보통 **내부망 PC**에서 작성하고, 기관 메일도 내부망에서 보낸다. 엑셀을 인터넷 PC로 옮기지 않아도 되도록
**인터넷 없이 더블클릭으로 열리는 관리 파일**을 만든다.
- `npm run build` 가 `index.html`(휴대폰 앱)과 함께 `dist/admin.html`을 만든다
- `admin.html`은 **완전 오프라인**: JSZip을 CDN이 아니라 파일 안에 내장(`node_modules/jszip/dist/jszip.min.js` 인라인, MIT 라이선스 주석 유지), 웹폰트 사용 안 함(시스템 글꼴), 외부 요청 0건
- 열 때 `window.isSecureContext`와 `crypto.subtle` 확인 → 없으면 "Chrome 또는 Edge로 열어 주세요" 안내 (`file://`에서도 Chromium 계열은 동작)
- 화면 흐름 (지시서 2의 `#admin` 화면에서 팀 칸 부분만 바꿈)
  1. 팀 비밀번호 입력 (저장하지 않음)
  2. 팀 이름 입력, 엑셀 선택 → 지시서 1 미리보기 (읽지 못한 칸 경고 포함)
  3. 이전에 만든 목록 파일을 갱신하는 경우: 「이전 목록 파일 불러오기」로 `.sajin`을 열면 `listId` 유지 + 바뀐 시설물 표시
  4. 「목록 파일 만들기」 → 암호화 → **복호화 검증** → `.sajin` 내려받기
  5. 다음 단계 안내를 크게 표시:
     "기관 메일에 이 파일을 첨부해 팀원에게 보내세요. 비밀번호는 메일에 적지 마세요."
     + 「메일 본문 복사」 버튼: 팀원 안내 문구(휴대폰에서 불러오는 방법 3단계, 앱 주소) — 비밀번호·시설물 정보는 넣지 않음
- 담당자가 `admin.html`을 내부망에 반입해야 하므로, `docs/대상목록_운영방법.md`에 "망연계로 HTML 파일 반입이 막히면 정보보안 담당자에게 반입 승인 요청" 안내 추가. 반입이 안 되는 경우 인터넷 PC에서 C-2 사용

### C-2. 웹 관리 화면 `#admin` (기존 유지, 변경)
- 팀 칸 선택·GitHub 업로드 안내를 **삭제**하고 C-1과 같은 흐름(파일 내려받기)으로 바꾼다. 코드는 C-1과 공유

### C-3. Claude Code 스크립트 (기존 변경)
- `npm run publish-list -- <엑셀> --team-name "3팀(부산권)"` → **`.sajin` 파일을 저장소 밖**(엑셀과 같은 폴더)에 만든다. `git` 작업 없음
- `--team`, `--clear`, `list-status`(서버 칸 관련) 제거
- CLAUDE.md의 "대상목록 올려줘" 작업 순서를 "대상목록 파일 만들어줘"로 교체 (미리보기 → 확인 → 파일 경로 안내 → "기관 메일로 보내세요")

### 추가·변경
- 목록 화면에 **「목록 파일 불러오기」** 버튼 (가장 눈에 띄게)
  - 파일 선택 칸은 `accept`를 지정하지 않는다 (아이폰 파일 선택 창에서 `.sajin`이 흐리게 막히는 문제 방지). 대신 내용으로 판별: `type: "sajin-list"`가 아니면 "대상목록 파일이 아닙니다"
  - 엑셀(`.xlsx`)을 고르면 지시서 1 F1 흐름으로 처리 (비상용, "이 휴대폰에서만" 표시)
- 처음 불러올 때 키가 없으면 지시서 2의 **팀 비밀번호 카드 → 내 이름 입력** 흐름 그대로
- 불러오기 결과
  - 새 목록: "3팀 · 26년 4차 · 7곳을 등록했습니다"
  - 같은 `listId`의 새 버전: 지시서 1 F5 병합 규칙 (사진·직접 고친 값 보존, 빠진 시설물은 "목록에서 빠짐")
  - 같은 `listId`의 **옛 버전**: "이미 더 최신 목록이 있습니다" 후 무시
- 팀 구분(이름 자동 / 팀 선택)은 지시서 2 그대로. 휴대폰에 여러 목록 파일을 불러와도 내 팀만 표시
- 시설물 구분 기준: **listId + 시설물명 + 날짜**
- 목록별 「이 목록 지우기」 (사진이 있는 시설물은 한 번 더 확인)
- 처음 사용자를 위한 빈 화면 안내: "팀장에게 받은 기관 메일의 첨부파일을 「파일에 저장」한 뒤 아래 버튼을 누르세요" + 그림 없는 3단계 안내

### 보고서 보내기 문구 변경
- 「메일로 보내기」를 누를 때와 저장 완료 문구를 **기관 메일 기준**으로:

  - 저장 완료: "파일 앱 › 다운로드에 저장했습니다. **기관 메일 앱**에서 새 메일 → 첨부 → 이 파일을 고르세요"
- 설정에 「보고서 받을 메일 주소」(선택, 휴대폰에만 저장)를 두고, 저장 완료 화면에 주소 복사 버튼 표시 (첨부는 메일 앱에서 직접)

## 7. 비밀번호 교체 (작업 A에서 이력이 있었거나, 인사이동·분실 시)
1. 담당자가 새 비밀번호를 `list-passphrase.txt`에 저장 (Claude Code는 파일을 열지 않음)
2. `npm run rotate-key` → `data/crypto.json`에 새 솔트 추가(`saltId` 새 이름) → 빌드 → 배포
3. 이후 만드는 `.sajin`은 새 비밀번호·새 솔트 사용. 휴대폰은 새 파일을 처음 열 때 새 비밀번호를 한 번 묻는다
4. 운영방법 문서에 "새 비밀번호는 구두 또는 내부 메신저로만 전달, 메일 본문에 적지 않기" 강조

2. 팀 비밀번호를 정해 팀장·실원에게 **구두나 내부 메신저로** 전달

**출장 전 (팀장)**
1. 내부망 PC에서 `admin.html` 더블클릭 (Chrome·Edge)
2. 비밀번호 → 팀 이름 → 엑셀 선택 → 미리보기 확인 → 「목록 파일 만들기」

**출장 전 (실원, 휴대폰)**
1. 기관 메일 앱에서 첨부파일 → 「파일에 저장」
2. 앱(사파리·크롬) → 「목록 파일 불러오기」 → 저장한 파일 선택
3. 처음이면 팀 비밀번호·내 이름 입력 → 우리 팀 목록 확인

**현장 이후**
- 보고서 「파일 저장」 → 기관 메일 앱에서 첨부해 발송 → 내부망에서 확인
