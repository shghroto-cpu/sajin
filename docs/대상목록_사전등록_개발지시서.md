## 1. 목적
지금(지시서 1 기준)은 실원 각자가 휴대폰에서 엑셀을 불러오거나 공유 링크를 눌러야 한다.
담당자가 원하는 방식은 다음과 같다.

- **PC에서 엑셀을 한 번 등록**하면
- **실원들은 휴대폰에서 앱 주소를 열기만 하면** 대상 시설물 목록이 이미 들어 있고, 바로 사진을 찍는다
- 현장은 인터넷이 되는 환경이다
- **사실관계조사는 여러 팀이 동시에 나갈 수 있다.** 팀마다 대상 시설물이 다르고, 각 팀이 **자기 목록을 직접 올릴 수 있어야** 하며(담당자 1명이 취합하지 않음), 휴대폰에는 **자기 팀 목록만** 보여야 한다

## 2. 방식: 암호화한 목록 파일을 앱과 함께 배포
```
[PC · 각 팀장 또는 담당자]                       [휴대폰 · 실원]
팀별 엑셀(대상목록)                               앱 주소 열기
   │  #admin 관리 화면 또는 Claude Code             │
   ▼                                              ▼
팀 비밀번호로 암호화 → data/lists/team-NN.enc ──GitHub──▶ team-01~10.enc 자동으로 받기
   (엑셀 원본은 올리지 않음)            Pages        │  최초 1회만 팀 비밀번호 입력
                                                  ▼
                                            휴대폰 안에서 복호화 → 대상 목록 표시
```
- GitHub 저장소는 **공개**이므로, 목록은 반드시 **암호화된 파일**로만 올린다. 비밀번호를 모르면 파일을 받아도 내용을 볼 수 없다
- 별도 서버·유료 서비스가 필요 없다 (지금 쓰는 GitHub Pages 그대로)
- **팀별 파일 칸(슬롯)**: `data/lists/team-01.enc` ~ `team-10.enc` 고정 이름 10칸. 팀마다 자기 칸에만 올리므로 **동시에 올려도 서로 덮어쓰지 않는다**. 목차 파일이 필요 없고, 휴대폰은 10칸을 모두 받아 본다(없는 칸은 건너뜀). 칸 수는 `data/crypto.json`의 `slots`로 조정
- 사진과 작성 내용은 지금처럼 **각자 휴대폰에만** 저장된다. 이 방식으로 올라가는 것은 엑셀에서 온 대상목록뿐이다

### 검토했지만 채택하지 않은 방식 (문서에 이유만 남길 것)
| 방식 | 채택하지 않은 이유 |
|---|---|
| 엑셀 내용을 그대로 GitHub에 올림 | 공개 저장소라 시설물 주소·연락처·직원 이름이 그대로 공개됨 |
| 외부 클라우드 DB(Firebase 등) | 기관 정보를 외부 서비스에 저장, 계정·보안 검토 부담 큼 |
| GitHub 비공개 저장소 | 유료이고, Pages 사이트 자체는 여전히 공개라 효과 없음 |
| 공유 링크만 사용(지시서 1 F4) | 출장마다 링크를 보내고 눌러야 함 → 보조 수단으로 유지 |
| 파일 하나(list.enc)에 전 팀 취합 | 담당자 1명이 모아야 하고, 동시에 올리면 서로 덮어씀 |
| 팀 목록 파일을 자유 이름으로 올리고 GitHub API로 폴더 조회 | API 이용 한도(시간당 60회/IP) 때문에 현장 휴대폰에서 실패 가능 |

## 3. 보안 설계 (반드시 이대로)
- 암호화: **AES-256-GCM** (Web Crypto API, 브라우저·Node 18+ 공통 `crypto.subtle`). 외부 라이브러리 추가 금지
- 비밀번호 → 키: **PBKDF2-SHA256, 600,000회**, 솔트(16바이트 무작위)는 `data/crypto.json`에 공개 보관 (솔트는 비밀이 아님)
- 파일마다 IV(12바이트) 새로 생성
- 휴대폰: 비밀번호를 **저장하지 않는다.** 처음 입력 시 키를 만들어 **추출 불가(non-extractable) CryptoKey**로 IndexedDB에 보관 → 다음부터 비밀번호 입력 없이 복호화
- 비밀번호 규칙: 12자 이상(예: 단어 3~4개를 띄어쓰기 없이 이어 붙인 문장). 짧으면 스크립트가 거부
- 비밀번호는 **저장소·코드·로그·커밋 메시지·Claude Code 대화에 절대 남기지 않는다**
  - PC에서는 담당자가 직접 만든 `list-passphrase.txt`(저장소 폴더 안, git 제외) 파일에서 스크립트가 읽는다
  - **Claude Code는 이 파일을 열거나 내용을 출력하지 않는다** (cat, 읽기 도구 사용 금지. 스크립트만 읽음)
- 비밀번호를 바꾸면(분실·인사이동 등) `data/crypto.json`의 솔트도 새로 만들고, 휴대폰은 복호화 실패 시 "팀 비밀번호가 바뀌었습니다" 안내 후 다시 입력받는다

### 암호화 파일 형식 (팀 칸 하나당 파일 하나)
```jsonc
// data/lists/team-03.enc  (JSON 텍스트 파일)
{
  "v": 1,
  "alg": "AES-256-GCM",
  "kdf": { "name": "PBKDF2-SHA256", "iter": 600000, "saltRef": "crypto.json" },
  "keyCheck": "…",          // 비밀번호 확인용: 고정 문자열을 같은 키로 암호화한 값 (틀린 비밀번호 즉시 판별)
  "iv": "base64…",
  "ct": "base64…",          // 아래 '내용'을 JSON → 암호화
  "publishedAt": "2026-10-28T09:00:00+09:00"   // 평문 메타데이터는 이것 하나만
}
// 복호화된 내용
{
  "slot": 3,
  "listVersion": "20261028-0900",          // 올릴 때마다 바뀜 → 휴대폰이 갱신 여부 판단
  "team": { "name": "3팀 (부산권)", "members": ["홍길동", "김철수"] },   // members는 엑셀 출장자 열에서 자동 수집
  "batch": { "id": "26-4", "name": "26년 4차 사실관계조사 시설물", "dates": ["2026-11-02", "2026-11-04"] },
  "sites": [ /* 지시서 1의 importer 결과 형식 (meta + no, buildings, phone, contact, travelers, dateLabel) */ ]
}
```
- 팀 이름·시설 수·시설물명 등은 평문에 넣지 않는다 (`publishedAt`만 평문)
- 모든 팀이 **같은 팀 비밀번호(실 공통)**를 쓴다. 팀별 비밀번호는 쓰지 않는다 (휴대폰 1대가 여러 팀 목록을 볼 수 있어야 하고, 관리가 복잡해짐)

## 4. PC 쪽: 목록 올리기 (두 가지 방법, 결과 파일은 같음)

| 누가 | 방법 | 필요한 것 |
|---|---|---|
| 앱 관리 담당자 | Claude Code 스크립트 (4-1) | 이 저장소, `list-passphrase.txt` |
| **각 팀장(누구나)** | **PC 브라우저 관리 화면 `#admin` (4-2, 필수)** | 인터넷 PC, 팀 비밀번호 |

### 4-1. Claude Code 스크립트

#### `scripts/publish_list.mjs` (`npm run publish-list -- <엑셀경로> --team <칸번호> [옵션]`)
1. 엑셀 경로는 **저장소 폴더 밖**이어야 한다. 안쪽이면 중단하고 "엑셀을 sajin-app 폴더 밖으로 옮겨 주세요" 안내
2. 지시서 1의 `src/xlsxreader.js` + `src/importer.js`로 읽기 (코드 중복 금지)
3. 미리보기를 터미널에 출력: 회차 이름, 시설 수, 연번·시설물명·날짜 목록, 읽지 못한 칸 경고
4. `list-passphrase.txt`가 없으면 중단하고 만드는 방법 안내 (아래 6장 1번)
5. `--team`(1~10) 필수. 그 칸에 이미 다른 팀 목록이 있으면 그 팀 이름·올린 시각을 보여주고 **덮어쓸지 확인** (다른 팀 칸을 실수로 덮지 않도록)
6. 팀 이름: `--team-name "3팀 (부산권)"`, 없으면 "N팀"
7. 암호화 → `data/lists/team-NN.enc` 저장 → **복호화 검증**(다시 풀어서 원본과 같은지) 후에만 성공 처리
8. 옵션
   - `--clear --team N`: 출장이 끝난 팀 칸 비우기 (파일 삭제)
   - `--no-contacts`: 연락처·담당자 제외 / `--no-travelers`: 출장자 이름 제외 (기본은 포함, 암호화되므로. 단 `--no-travelers`면 휴대폰 자동 팀 구분이 안 되므로 경고)
9. `npm run list-status`: 10칸 각각의 팀 이름·회차·시설 수·올린 시각 표 출력 (복호화해서 PC 화면에만 표시, 파일로 저장하지 않음)

### `scripts/rotate_passphrase.mjs` (`npm run rotate-key`)
- `list-passphrase.txt`의 **새 비밀번호**와 `list-passphrase.old.txt`의 **이전 비밀번호**로 **모든 팀 칸**을 다시 암호화하고 `data/crypto.json` 솔트 교체. 끝나면 old 파일 삭제 안내

### `scripts/check_safe_to_commit.mjs` (커밋 전 자동 검사, `npm run precommit`)
- 스테이징된 파일 중 `*.xlsx, *.xls, *.hwp, *.hwpx, list-passphrase*.txt`가 있으면 **중단**
- `data/lists/*.enc`가 암호화 형식(JSON + `ct` 필드)이 아니면 중단
- 스테이징된 텍스트 파일에서 전화번호 형태(`0\d{1,2}-\d{3,4}-\d{4}`)가 보이면 경고 후 중단 (테스트 가짜 값 `000-0000-0000` 형식은 허용)
- git `pre-commit` 훅으로 연결 (`.githooks/pre-commit` + `git config core.hooksPath .githooks`)

### Claude Code 작업 규칙 (CLAUDE.md에 추가)
담당자가 "대상목록 올려줘 (엑셀 경로)"라고 하면:
1. 몇 번 칸(팀)인지 담당자에게 확인 (`npm run list-status`로 빈 칸·사용 중인 칸을 먼저 보여줌)
2. `npm run publish-list -- "<경로>" --team N --team-name "…"` 실행 → 미리보기를 보여주고 **「올릴까요?」 확인**
3. 확인 후 `git add data/lists/team-NN.enc data/crypto.json` → 커밋 메시지 `대상목록 갱신 (N팀, 회차명, N곳)` → `git push`
4. 3분 뒤 배포 주소의 해당 칸 파일이 갱신됐는지(`publishedAt`) 확인
4. 담당자에게 "실원들은 앱을 새로고침하면 목록이 보입니다" 안내
- `git add -A`, `git add .` 사용 금지 (엑셀이 섞여 올라가는 것 방지)

### 4-2. PC 브라우저 관리 화면 `#admin` (필수 — 각 팀장이 직접 올리는 방법)
앱 주소 뒤에 `#admin`을 붙여 PC 브라우저로 연다. Claude Code·개발 도구 없이 쓸 수 있어야 한다.
1. **팀 비밀번호 입력** → 현재 10칸 현황 표시 (팀 이름·회차·시설 수·올린 시각·비어 있음)
2. **내 팀 칸 선택**: 빈 칸 또는 우리 팀이 쓰던 칸. 다른 팀이 쓰는 칸을 고르면 "○팀이 사용 중(10.28 09:00 올림). 덮어쓸까요?" 경고
3. **팀 이름 입력** (예: 3팀 (부산권)), **엑셀 선택** → 지시서 1 F1과 같은 미리보기 (읽지 못한 칸 경고 포함)
4. 「암호화 파일 만들기」 → 브라우저 안에서 암호화·복호화 검증 → `team-03.enc` 내려받기
5. 화면에 다음 단계 안내를 크게 표시 (둘 중 하나)
   - **직접 올리기**: GitHub 저장소 → `data/lists` 폴더 → 「Add file › Upload files」 → `team-03.enc` 끌어놓기 → 「Commit changes」 (팀장에게 저장소 쓰기 권한 필요: 6장 참고)
   - **담당자에게 전달**: `team-03.enc` 파일을 담당자에게 메일로 보내기 (암호화된 파일이라 엑셀을 보내는 것보다 안전). 담당자가 Claude Code로 올림
6. 「이 팀 칸 비우기」: 빈 내용을 암호화한 파일을 만들어 같은 방법으로 올림 (출장 종료 시)
- 이 화면은 비밀번호·엑셀 내용을 **저장하지 않는다** (화면을 닫으면 사라짐). 엑셀은 브라우저 밖으로 전송하지 않는다
- 휴대폰 화면 크기에서도 깨지지 않게 하되, 주 사용 환경은 PC

## 5. 휴대폰 쪽: 앱 동작

### 목록 받아오기
- 앱을 열 때, 목록 화면으로 돌아올 때, 앱이 다시 화면에 보일 때(`visibilitychange`) 그리고 목록 화면의 「새로고침」 버튼:
  `data/crypto.json`의 `slots` 수만큼 `fetch('data/lists/team-NN.enc?t=' + Date.now(), { cache: 'no-store' })`를 **동시에** 요청 (404는 빈 칸으로 처리)
  (GitHub Pages는 약 10분 캐시가 있으므로 반드시 캐시 무시)
- 칸별로 받은 `listVersion`이 휴대폰에 있는 것과 같으면 아무것도 안 함
- 새 버전이면 복호화 → **지시서 1 F5 병합 규칙**으로 반영. 단 시설물 구분 기준은 **팀 칸 + 시설물명 + 날짜** (다른 팀이 같은 시설물을 가도 섞이지 않게). 현장에서 고친 값(`edited`)·사진은 보존, 빠진 시설물은 "목록에서 빠짐" 표시만
- 칸이 비워지면(파일 삭제·빈 목록) 그 팀 목록은 "출장 종료" 묶음으로 내리고, 사진이 있는 시설물은 사용자가 지울 때까지 보존
- 반영 후 화면 위에 잠깐 안내: "3팀 대상 목록이 갱신되었습니다 (26년 4차 · 7곳)"

### 우리 팀 목록만 보기 (팀 구분)
- 처음 비밀번호를 입력한 직후 **「내 이름」** 입력 (선택, 휴대폰에만 저장)
- **자동 구분**: 각 팀 목록의 `team.members`(엑셀 출장자 열)에 내 이름이 있는 팀만 표시
- 이름을 입력하지 않았거나 어느 팀에도 없으면 **팀 선택 화면**: "어느 팀 목록을 볼까요?" + 팀 이름·회차·날짜 카드 → 고른 팀만 표시 (여러 팀 선택 가능)
- 목록 화면 위쪽에 현재 보는 팀 표시 + 「다른 팀 보기」(전체 팀 펼치기, 기본 접힘)
- 다음 출장에서 팀 구성이 바뀌어도 이름 기준이면 자동으로 새 팀 목록이 보임. 팀을 직접 고른 경우 그 칸 내용이 바뀌면(회차가 달라지면) 팀 선택을 다시 물음
- 엑셀 출장자 열 이름은 공백 제거 후 비교 ("홍 길동" = "홍길동")
- **인터넷이 끊기거나 파일이 없으면** 마지막으로 받은 목록 그대로 사용. 오류 문구 대신 회색 글씨 "마지막 갱신: 10.28 09:00"
- 팀 칸 파일이 하나도 없으면(아직 아무것도 안 올린 상태) 지금처럼 「엑셀 불러오기 / 직접 입력」 화면

### 팀 비밀번호 (처음 한 번)
- 처음 팀 칸 파일을 받았는데 키가 없으면 목록 자리에 카드 하나:
  "등록된 대상 목록이 있습니다. 팀 비밀번호를 입력하세요" + 입력칸 + 「확인」
- `keyCheck`로 즉시 판별 → 틀리면 "비밀번호가 맞지 않습니다" (5회 연속 틀리면 30초 대기)
- 맞으면 키 저장 → 바로 목록 표시. 이후로는 묻지 않음
- 설정(⋯) 메뉴: 「팀 비밀번호 다시 입력」, 「이 휴대폰에서 대상 목록·키 지우기」

### 기존 기능과의 관계
- 휴대폰에서 직접 엑셀 불러오기(지시서 1 F1), 공유 링크(F4)는 **그대로 둔다** (비상용). 직접 불러온 회차는 "이 휴대폰에서만" 표시
- 같은 회차를 서버 목록과 직접 불러오기 양쪽으로 받았으면 F5 규칙으로 하나로 합친다
- 저장 파일 이름은 지시서 1 규칙 그대로 (팀 이름은 넣지 않음)

## 6. 담당자 운영 절차 (구현 후 이 내용을 `docs/대상목록_운영방법.md`로 만들어 줄 것)

1. **팀 비밀번호 정하기**: 12자 이상, 예) 단어 3~4개를 붙인 문장. 실원에게는 **구두나 내부 메신저로만** 전달
2. **비밀번호 파일 만들기** (담당자가 직접, Claude Code에게 비밀번호를 말하지 않음)
   - 메모장 열기 → 비밀번호만 한 줄 입력 → 「다른 이름으로 저장」 → 위치: `sajin-app` 폴더, 파일 이름: `list-passphrase.txt`

4. **팀 칸 번호 정하기**: 예) 1~3번 상시 팀, 4~10번 임시 팀. 표로 만들어 실 공유 (`docs/대상목록_운영방법.md`에 표 양식 포함)
5. **팀장이 직접 올릴 경우**: 팀장이 GitHub 계정을 만들면 담당자가 저장소 → Settings → Collaborators → 「Add people」로 초대 (쓰기 권한). 계정을 안 만들 팀은 4-2의 「담당자에게 전달」 방식 사용

### 출장 전 (매번, 팀마다 각자)
- **팀장이 직접**: PC 브라우저로 `앱주소#admin` → 비밀번호 → 우리 팀 칸 선택 → 팀 이름·엑셀 선택 → 파일 만들기 → GitHub `data/lists`에 업로드 (또는 담당자에게 메일)
- **담당자가 Claude Code로**: `대상목록 올려줘: 3번 칸, 3팀(부산권), C:\Users\…\Desktop\3팀_대상목록.xlsx`
- 엑셀 출장자 열에 **팀원 이름을 정확히** 적어야 휴대폰에서 자동으로 팀이 구분됨
- ✅ 확인: 3분 뒤 팀원 휴대폰에서 앱 새로고침 → 우리 팀 목록만 보이면 완료

### 실원 (처음 한 번만)
앱 주소를 사파리·크롬으로 열기 → 팀 비밀번호 입력 → 내 이름 입력 → 이후에는 열기만 하면 **우리 팀** 최신 목록

### 출장이 끝나면
해당 팀 칸 비우기 (`#admin`의 「이 팀 칸 비우기」 또는 Claude Code에 "3번 칸 비워줘") → 다음 팀이 그 칸을 사용 가능 (휴대폰의 사진·작성 내용은 지워지지 않음. 각자 보고서 저장 후 「목록 비우기」)
